1. TOPIC OVERVIEW & OBJECTIVES
================================================================================
Modern packaged and prepared foods often conceal high levels of refined sugar,
palm oil, synthetic preservatives, and high sodium under complex scientific or
industrial terminology. Consumers rarely have the time or specialized nutrition
knowledge to decode ingredient lists while shopping or dining.

The "Food Label Reader" is an end-to-end intelligent system designed to bridge
this gap using Artificial Intelligence and Computer Vision. It provides:
1. Automated Label Reading: Extracts ingredient text directly from food packages
   using OCR (Optical Character Recognition).
2. Visual Food Recognition: Identifies prepared dishes from real-world photos
   using a Deep Convolutional Neural Network (CNN - MobileNetV2).
3. Barcode Lookup: Queries public international food databases (OpenFoodFacts)
   via UPC/EAN barcodes.
4. Intelligent Health Scoring: Analyzes detected ingredients using a scoring
   algorithm that penalizes toxic/ultra-processed additives and rewards wholesome
   nutrients, producing an intuitive score (0-100) and healthy alternatives.

--------------------------------------------------------------------------------
3.1 Module 1: Optical Character Recognition (OCR) Pipeline
--------------------------------------------------------------------------------
File: app.py -> Route: /extract
Core Libraries: OpenCV (cv2), PIL (Pillow), Pytesseract

How it works step-by-step:
1. Image Ingestion: The user uploads an image of an ingredient label.
2. Grayscale Conversion: cv2.cvtColor(img, cv2.COLOR_BGR2GRAY) converts the 3-channel
   RGB image to single-channel luminance, discarding confusing color variations.
3. Otsu's Binarization: cv2.threshold(..., cv2.THRESH_BINARY + cv2.THRESH_OTSU)
   dynamically calculates the optimal threshold value separating text ink from the
   background package plastic or cardboard.
4. Noise Reduction: cv2.medianBlur(gray, 3) eliminates salt-and-pepper artifacts,
   dust, or grain caused by camera sensors.
5. OCR Extraction: pytesseract.image_to_string(pil_img, lang="eng") performs
   line segmentation, character isolation, and LSTM-based text recognition.
6. Sanitization: Strips trailing whitespace, linebreaks, and non-printable noise.

--------------------------------------------------------------------------------
3.2 Module 2: Deep Learning Food Image Classifier (MobileNetV2)
--------------------------------------------------------------------------------
Files: app.py, train_food_model.py, fine_tune_model.py
Weights: food_model_finetuned.h5 (or food_model.h5)
Architecture: MobileNetV2 (Transfer Learning from ImageNet)

Categories Recognized (10 Indian Food Classes):
0: Pav Bhaji
1: Vada Pav
2: Samosa
3: Dhokla
4: Idli Wada
5: Aloo Paratha
6: Kachori
7: Pani Puri
8: Steam Momos
9: Vegetable Sandwich

How it works step-by-step:
1. Preprocessing:
   - Resize input image to target dimension: 224 x 224 pixels.
   - Convert to 3-channel RGB.
   - Convert uint8 pixel values [0, 255] to float32 normalized tensor [0.0, 1.0].
   - Expand dimensions to create batch tensor: shape (1, 224, 224, 3).
2. Feature Extraction:
   - Passes through MobileNetV2 depthwise separable convolution blocks, capturing
     hierarchical visual features (edges, textures, shapes, food toppings).
3. Classification Head:
   - GlobalAveragePooling2D: Flattens spatial dimensions into a feature vector.
   - Dropout(0.4): Prevents overfitting during training.
   - Dense(128, activation='relu'): Intermediate dense representation.
   - Dense(10, activation='softmax'): Output layer producing probability distribution
     summing to 1.0 across all 10 food classes.
4. Inference:
   - np.argmax(preds[0]) extracts the index with the highest probability.
   - confidence = np.max(preds[0]) yields certainty (0.0 to 1.0).

3.3 Module 3: Barcode Scanner & OpenFoodFacts API Integration
--------------------------------------------------------------------------------
File: app.py -> Route: /barcode
External Endpoint: https://world.openfoodfacts.org/api/v0/product/{barcode}.json

How it works step-by-step:
1. Client supplies barcode string (e.g. UPC/EAN from packaging).
2. Server queries OpenFoodFacts public database with a 5-second timeout.
3. If found, extracts official product title, registered ingredients text, and
   nutritional values per 100g (energy-kcal, proteins, fat, saturated-fat, sugars, salt).
4. Pipes the retrieved ingredients text directly into the health evaluation engine.

3.4 Module 4: Ingredient Analysis & Health Scoring Mathematical Engine
--------------------------------------------------------------------------------
File: app.py -> Function: evaluate_ingredients(text)

Harmful Ingredients Dictionary:
- sugar, salt, refined, oil, palm, flavor, preservative, color, acid,
  benzoate, fructose, msg, artificial, hydrogenated, maida, corn syrup,
  sweetener, margarine, glucose, starch, sodium, stabilizer.

Healthy / Wholesome Ingredients Dictionary:
- fiber, protein, vitamin, mineral, whole grain, natural, honey, oats,
  seeds, nuts, fruit, vegetable, olive oil, yogurt, herb, plant-based.

Mathematical Scoring Algorithm:
1. Count matches:
   N_harmful = count(harmful_words in text)
   N_good    = count(good_words in text)

2. Penalty and Bonus:
   harmful_penalty = N_harmful * 12
   good_bonus      = N_good * 4

3. Balance Factor:
   balance_factor = (N_good + 0.5) / (N_good + N_harmful + 1.0)

4. Score Equation:
   raw_score = 90 * balance_factor - (harmful_penalty * 0.7) + good_bonus
   final_score = clamp(raw_score, min=20, max=100)

Rating Tiers:
- Score >= 85 : "Excellent"
- Score >= 70 : "Healthy"
- Score >= 50 : "Moderate"
- Score >= 30 : "Unhealthy"
- Score < 30  : "Very Unhealthy"

Substitution Engine:
- If "sugar" detected   -> Suggests Stevia or Honey
- If "salt" detected    -> Suggests Low-Sodium Salt or Herbs
- If "oil" / "refined"  -> Suggests Olive or Cold-Pressed Sunflower Oil
- If "maida" detected   -> Suggests Whole Wheat Flour / Millets

6. KEY INSIGHTS, EDGE CASES & RECOMMENDATIONS
================================================================================
1. Key Matching Inconsistency:
   In app.py, the class name is "Vegetable Sandwich", which converts to
   "vegetable_sandwich". In indian_food_info.csv, the key is named "sada_sandwich".
   Recommendation: Add an alias map in app.py:
   {"vegetable_sandwich": "sada_sandwich"} to ensure seamless CSV lookup.

2. Windows Console UTF-8 Encoding:
   When running Python scripts on Windows, emojis in print statements (e.g. checkmark
   or cross) trigger UnicodeEncodeError under default cp1252 codepage.
   Recommendation: Include `sys.stdout.reconfigure(encoding='utf-8')` or run
   with `PYTHONIOENCODING=utf-8`.

3. OCR Contrast & Preprocessing:
   Complex curved packaging causes glare. Implementing adaptive thresholding or
   perspective correction in cv2 improves OCR accuracy by up to 25%.

4. Expanding Dataset Classes:
   The current classifier supports 10 popular Indian street foods/snacks.
   Expanding the dataset with transfer learning to include more packaged foods
   will further unify the vision and label-reading pipelines.
